# Supabase account boundary

Supabase Auth has been selected for Slim Maat, but no Supabase project is provisioned, no SDK is installed/configured here and this isolated module is not mounted. It wraps an injected Supabase client and offers signup, email/password signin, local-device signout and server-checked user lookup. Return values deliberately exclude raw credentials and tokens. A successful signUp means the request was accepted, not that the email is confirmed or the user may use chat. Always keep confirmation enabled and show a neutral response to avoid account enumeration.

Before real use: create a separate project and configure official SDK plus email confirmation, redirect allow-list, custom SMTP for public users, abuse protections and secure session handling. Confirm SDK behavior against the deployed version and run integration tests. Users must independently pass 18+ verification, stored in server-controlled records inaccessible to user writes. Supabase login is not proof of age. Do not map getUser alone into adultAccess authenticated/revoked flags: Supabase documents that an unexpired JWT can survive signout; a server-side auth.sessions session-id existence check is needed for immediate revocation guarantees. Also implement rate limiting, origin/CSRF protection, secure per-user storage policies and opt-in consent, export and deletion. AI remains disabled until all controls are implemented and tested. Never put secrets into the repository.
