# Conversation storage foundation (not deployed)

This is an isolated development prototype for future account-based conversation history. It is not wired into the app, not a migration in production, and does not enable AI, autosave, or sync. `history-schema.sql` proposes owner-scoped tables, row-level security, and cascade deletion. Signed-in clients may only insert user messages; assistant messages must come from a trusted server. `historyStore.js` is an unconnected browser adapter with basic validation and generic errors. Its current 100 conversation / 500 message result limits require pagination before release; it does not yet provide a complete export feature.

A separate `history-memory-demo.js` fixture supports synthetic conversation create/list/read/delete tests in memory only. The standalone `history-demo.html` development screen uses only fixed examples and is linked in the private account preview build for testing; it is not connected to accounts, storage, AI or the database. It has no account or database connection, does not persist or synchronize, and must not be used to claim real user isolation or handle real conversations. It does not simulate AI replies. Automated UI tests use a simulated DOM. The original HTML, CSS and JavaScript sources were also loaded into a browser via temporary blob URLs in a 390px-wide iframe; create, select, confirm/cancel deletion and clearing on reload passed. The native confirmation dialog was separately exercised in a browser with an inlined copy. This does not replace testing the unmodified standalone page served normally or testing on a physical device.

Before any deployment: independently review the SQL, privileges, indexes and database ownership; apply only in an isolated test database; test row policies and delete cascade against two real authenticated users and anonymous users, including attempts to insert foreign owner IDs, read/write/delete another user's data, forge assistant messages, bypass field limits and call after signout/revocation. Review the Supabase API configuration and RLS defaults. Include privacy notice, opt-in, retention, export and account deletion. Agree storage costs and abuse safeguards. Verify how the trusted AI backend associates assistant messages with the authenticated owner. Add pagination, concurrency behavior and error handling in the UI before describing history or sync as functional. Browser clients must never contain a service-role key. These checks do not replace server authentication or independent adult eligibility for AI.

Unit tests use a mocked client. The disposable PostgreSQL test in `history-isolation.test.sql` exercises the real schema and row policies with two simulated identities, a missing subject and an anonymous role. On 2026-11-11 it passed locally in a newly created, temporary PostgreSQL database, which was then removed. The test must only run on an empty disposable database. It is not a Supabase integration test and does not verify real authentication, session revocation, platform configuration, AI calls, or cross-device sync. Testing with two real authenticated test users on an isolated Supabase project remains required. The current installed account app remains unchanged.
