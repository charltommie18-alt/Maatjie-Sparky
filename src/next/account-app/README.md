# Slim Maat private account integration (development only)

This isolated test app is not mounted in the original app. Registration is hard-disabled in the controller and adapter regardless of supplied public configuration: it cannot create a Supabase account. It can only attempt sign-in to an existing account after explicit public configuration is supplied, and is not release-ready. AI remains disconnected and email confirmation is not age verification. Do not deploy publicly or use real users until the security, privacy and end-to-end checks are complete.

Node 20 and pnpm are needed. In this directory run `pnpm install --frozen-lockfile`. Supply `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` through a local ignored `.env.local` or process environment; use only the intended Slim Maat project, never a secret/service-role key. Missing/invalid config or unavailable session storage disables the UI. Start `pnpm dev` on loopback. This private test stores the Supabase session in browser sessionStorage, scoped to the tab, to test recovery on reload. The browser can refresh tokens; the screen verifies the user with Supabase before showing signed-in state. Local signout clears that tab's session. Tokens in browser storage remain accessible to scripts running on that origin, so use a trusted private test environment only. This is not a final multi-device session design; URL session detection remains disabled.

Do not configure Supabase or attempt a real login for this preview. Registration remains disabled even if public configuration is later supplied. If a future authorised test needs sign-in for an existing account, it must first complete the security and deployment review. Never paste credentials or passwords into chat.

Tests use mock clients: they do not prove email delivery or live authentication. A production launch still requires session persistence/refresh design, password reset, server-side token verification, independent adult eligibility, rate limits, moderation, RLS and retention/export/delete policy, redirect and SMTP configuration, security review and real end-to-end testing. The old preview remains a no-network mock.
